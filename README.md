# Bohack 简历工作台

Bohack 是一个本地运行的招聘简历阅读与分析工作台。它可以导入 PDF、整理候选人、在应用内阅读原始简历，并通过可配置的 AI Agent 对照职位要求分析简历。PDF 和候选人数据默认保存在运行本项目的电脑上。

## 功能

- 在左侧简历库搜索并切换候选人。
- 导入单份 PDF、多份 PDF，或选择整个文件夹批量导入。
- 将原始 PDF 和候选人信息保存到本地简历目录。
- 使用应用内阅读器查看 PDF，支持翻页、缩放和下载。
- 在 PDF 上方提供透明文字层，并可用一个开关显示或隐藏全部奖项黄色标注。
- 自动加载 PDF.js 中文字符映射与标准字体资源，支持包含中文 CID 字体的 PDF。
- 提取 PDF 文本，并调用模型识别姓名、岗位、地点、教育背景、技能和简介。
- 导入完成后自动生成一份初始候选人分析报告；填写职位要求后可继续生成岗位匹配报告。
- 粘贴职位要求，让 Agent 汇总证据、差距、建议追问及辅助评分。
- 分析工作区提供常用任务快捷入口；“联网参考岗位背景”是显式开关，打开后只根据职位要求搜索公开资料，不发送候选人简历。
- 职位要求旁提供 AI 整理岗位重点功能，结果先以草案展示，审核员可采用或保留原文。
- 为领导力、专业能力、经验、经历广度、岗位契合度和进步分生成评分卡；综合分按可调权重加权计算。
- 支持手动修改评分权重，也支持让 AI 提出调整方案；方案会先预览综合分和当前排名变化，由审核员确认后应用；“候选人对比”视图按综合分排名展示多人分项得分。
- 分析文档内置六项能力雷达图、综合分-时间趋势折线图，以及将项目和技术术语转换为审核员易懂表述的项目拆解卡。
- 分析文档增加综合分贡献拆解：同时显示单项分数、权重、实际贡献值和证据置信度，便于解释综合分来源。
- 点击评分历史中的证据句子可以回到 PDF 原文并定位高亮；无法精确匹配时会明确提示，不使用模糊匹配冒充证据位置。
- 分析报告会把当前候选人与本地历史同岗位样本比较，显示“超过历史样本 X%”的百分位标记，并展示首轮通过线、录取线和样本通过率。
- 内置多份产品、运营、数据、前端、后端和用户研究示例简历，便于直接体验多人对比和招聘质量图。
- 新增资料库入口，支持查询、增改和删除本地竞赛、期刊 / 会议及公司资料；删除前会提示受影响的简历引用，详情中的引用可跳回 PDF 命中词；审核员可填写可解释的含金量评分与备注。
- 可选接入 Tavily 网页搜索；分析 Skill 位于 `server/skills/resume-analysis.md`。
- 从工作台打开本地简历文件夹，或将已有文件夹中的 PDF 导入工作台。

## 环境要求

- Node.js 20 或更高版本
- npm
- 一个兼容 OpenAI Chat Completions 接口的模型服务及 API Key
- Tavily API Key（可选；不配置时 Agent 不会进行网页搜索）

## 安装和启动

在项目根目录运行：

```powershell
npm install
```

在项目根目录新建 `.env` 文件，并按下一节填写配置。然后启动前端和本地 Agent 服务：

```powershell
npm run dev
```

`npm run dev` 和 `npm run build` 会自动从 PDF.js 复制中文 CMap 与标准字体到本地静态资源目录，无需手动下载。该生成目录已忽略，不会提交到 Git。

Vite 默认地址为 `http://127.0.0.1:5173/`。开发服务器仅监听本机回环地址。首次启动或修改 `.env` 后，请重启 `npm run dev`，让 Agent 服务重新读取配置。

## 环境变量

在项目根目录新建 `.env`，内容格式如下。替换示例占位值，不要把真实密钥放进代码、README 或提交记录。

```dotenv
# 必填：模型服务 API Key
OPENAI_API_KEY=your_model_api_key

# 可选：OpenAI 兼容服务的 API 根地址。
# 官方 OpenAI 服务使用默认值；第三方服务请填写服务商给出的 /v1 地址。
OPENAI_BASE_URL=https://api.openai.com/v1

# 必填：模型服务中实际可用的模型名称
OPENAI_MODEL=gpt-4.1-mini

# 可选：Tavily 搜索 API Key；可在 https://app.tavily.com/ 获取
TAVILY_API_KEY=your_tavily_api_key

# 可选：本地 Agent API 端口，默认 8787；开发前端代理会自动跟随此端口
PORT=8787

# 可选：简历文件夹。相对路径以项目根目录为基准；默认 .data/resumes
RESUME_DIR=.data/resumes
```

### 模型服务配置

`OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL` 必须对应同一个服务商账号和服务端点。`OPENAI_BASE_URL` 应是 API 根地址，应用会调用其 Chat Completions 接口。若使用 OpenAI 官方服务，可使用上面的默认地址；若使用兼容服务，请按服务商文档填写地址和模型标识。模型需要支持 Chat Completions、工具调用以及简历信息提取所需的普通对话请求。

### Tavily 搜索配置

从 Tavily 控制台创建 API Key 后填入 `TAVILY_API_KEY`。配置为空时，模型分析仍可使用，但网页搜索不可用。配置非空时，Agent 会在认为有助于回答时调用搜索工具；简历分析 Skill 限制搜索内容为职位相关公开信息，不允许借搜索调查候选人的敏感或私人信息。

## 简历文件夹和 PDF 导入

默认目录为项目根目录下的 `.data/resumes/`。每个导入的 PDF 会复制到此目录，候选人元数据保存在其 `.metadata/` 子目录。`.data/` 已加入 `.gitignore`，简历文件不会被 Git 跟踪或推送到 GitHub。

侧栏的“导入 PDF 简历”用于选择一个或多个文件；“导入文件夹”可选择一个已有目录并导入其中的 PDF；“打开存储位置”会在本机文件管理器中打开工作台自己的简历目录。也可以把 PDF 放入 `RESUME_DIR` 指定的目录，再刷新工作台，由服务扫描并索引新文件。

文本型 PDF 会提取文字，并尝试由模型识别候选人基本信息。扫描件或图片型 PDF 仍可在阅读器中查看，但当前版本没有 OCR，因此无法从纯图片页面提取文字或据此分析。请人工核对模型提取的信息和分析结果；评分仅作参考，不应单独作为招聘决定。

## 评分与候选人对比

默认评分权重为：领导力 18%、专业能力 24%、经验 20%、经历广度 10%、岗位契合度 23%、进步分 5%。综合分公式为 `Σ(单项分数 × 权重) / Σ权重`，服务端会将手动输入或 AI 建议的权重归一化为 100%。AI 建议不会直接保存；审核者可先看六项权重变化、当前候选人的综合分变化和同岗位族排名变化，再选择应用或丢弃。示例档案会在预览中单独计数。导入 PDF 或重新分析时，分析报告与评分卡并行生成以减少等待；两项都成功后才保存，综合分始终由服务端计算。多人对比表以数值条辅助横向比较；点击候选人的证据摘要可回到简历分析并尝试在 PDF 原文定位。

“经历广度”只评价与工作相关的行业、领域、方法和团队经历，不使用性别、民族、年龄、国籍、残障、宗教、婚育等受保护属性。评分卡保存于候选人的 `.metadata/<id>.json`，当前权重保存于 `.metadata/settings.json`。分析文档会显示综合分和六项评分；顶部“候选人对比”可查看所有候选人的分项得分和排名。

“联网参考岗位背景”默认关闭。打开后，PDF 分析会用职位要求生成有限的公开网页检索，结果只作为岗位背景线索传给 Agent，并在工作区列出来源；它不能证明候选人的个人经历。没有 Tavily 配置或检索失败时，分析仍会继续，并显示降级状态。通用 Agent 也使用同一开关控制工具调用，避免在未明确需要时产生额外搜索延迟。

分析文档的“综合分复评记录”只绘制实际保存的评分结果。点击某个历史点可以查看当次六项分数、证据、岗位要求和评分权重；导入 PDF 时记录初评，之后每次成功复评追加一条历史。示例简历不伪造趋势数据。

### 历史招聘基准库

`shared/history.ts` 提供本地演示样本；顶部“历史样本”入口可新增、编辑、删除本地样本，并按岗位族和年份筛选。样本管理页新增 0–19、20–39、40–59、60–79、80–100 五档分布，条形长度表示当前岗位 / 年份筛选下的样本数，颜色区分最终录取、仅通过首轮和未过首轮；点击区间或结果图例会联动筛选记录与下方分数轨道，分数段和招聘结果可以组合筛选。还可输入自然语言生成筛选草案，确认后应用；此请求只发送筛选指令、可用岗位族和年份，不发送历史样本记录。样本图中的点与记录列表也互相联动；本地维护数据写入 `.data/resumes/.metadata/history-candidates.json`，不会推送到 GitHub。系统只存匿名代号、岗位、年份、综合分和首轮/录取结果，不存历史简历正文。分析报告中的分布图按岗位族计算百分位，只统计综合分严格低于当前分数的历史记录，例如“超过历史样本 67%”表示 67% 的同口径样本分数更低，同分记录不计入超过比例。首轮通过线和录取线是样本中位数参考值，不是硬性录用规则。种子记录为虚构演示数据；正式使用前应导入经授权和脱敏的汇总结果。

实际部署时应将种子数据替换为经过授权和脱敏的招聘记录，并保留样本年份、岗位口径和评分版本，避免把不同岗位或不同评分标准直接混在一起比较。

### 竞赛、期刊与公司资料库

顶部“资料库”入口打开本地资料查询工作区。资料支持按类别、核验状态、人工评分区间和是否被简历引用筛选，支持关键词搜索和按名称、评分或更新时间排序；列表会显示每条资料被多少份简历引用。分类分布和人工评分分段图均可点击筛选，评分分布固定以全部资料为统计范围；核验均分只统计已核验条目。可新增或修订资料名称、别名、来源、简介和审核信号，别名会参与简历交叉引用。审核员可以保存人工含金量评估及核验状态，也可以给 AI 提供岗位背景和自然语言评估侧重，例如优先核对官方赛果、降低宣传材料权重。AI 建议会先作为独立草案展示分差、理由、置信度和核验问题；审核员确认采用后才会填入评分表，之后仍需点击保存。评估侧重不能覆盖证据规则。每次人工保存会追加一条可点击查看的评分历史，明确区分人工填写与经人工确认的 AI 建议。搜索不可用时会明确标注降级状态。联网核验只发送资料条目的名称、领域和组织，不发送候选人简历。示例数据位于 `shared/knowledge.ts`；自定义资料和人工评估保存在 `.data/resumes/.metadata/`，不会提交到 GitHub。

资料库 API 为 `GET /api/resumes/knowledge`、`POST /api/resumes/knowledge`、`POST /api/resumes/knowledge/enrich`、`PUT /api/resumes/knowledge/:id`、`PUT /api/resumes/knowledge/:id/review` 和 `POST /api/resumes/knowledge/:id/suggest`。资料草案和评分建议分别使用 `server/skills/knowledge-enrichment.md`、`server/skills/knowledge-assessment.md` 约束证据口径；前者只填充未保存表单，后者只提供待人工确认的评估。Tavily 返回的网页摘要只是检索线索，系统不宣称已独立核实网页内容。通用 Agent 与资料核验共用搜索适配器，对相同查询短时缓存、合并并发请求；失败不缓存。分析报告和资料详情支持双向跳转；引用仅由简历中出现的资料名称或别名确定性匹配，不代表已核实。示例评分只用于演示界面和审核流程，使用真实招聘时应核对官方来源、具体名次、作者贡献、岗位职责和项目结果。

## 数据与隐私

- `.env`、`.env.*`、`.env.example` 和 `.data/` 均被 Git 忽略。项目不会提供可提交的密钥模板；请在本机创建 `.env`。
- 简历 PDF 和提取文本保存在本机 `RESUME_DIR`，不会因为导入操作自动上传到 GitHub。
- 导入 PDF 时，提取出的简历文本会发送给 `.env` 中配置的模型，用于整理候选人基本信息。用户主动运行分析时，简历文本、职位要求和提问也会发送给模型服务。
- 若 Agent 调用 Tavily，发送给搜索服务的是搜索查询和搜索请求，不会自动上传整份 PDF。
- 请确认你的模型和搜索服务的数据处理方式符合组织的招聘、隐私和数据保留要求。
