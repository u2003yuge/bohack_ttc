# Bohack 简历工作台

Bohack 是一个本地运行的招聘简历阅读与分析工作台。它可以导入 PDF、整理候选人、在应用内阅读原始简历，并通过可配置的 AI Agent 对照职位要求分析简历。PDF 和候选人数据默认保存在运行本项目的电脑上。

## 功能

- 在左侧简历库搜索并切换候选人。
- 导入单份 PDF、多份 PDF，或选择整个文件夹批量导入。
- 将原始 PDF 和候选人信息保存到本地简历目录。
- 使用应用内阅读器查看 PDF，支持翻页、缩放和下载。
- 在 PDF 上方提供透明文字层，并可用一个开关显示或隐藏全部奖项黄色标注。
- 自动加载 PDF.js 中文字符映射与标准字体资源，支持包含中文 CID 字体的 PDF。
- 提取 PDF 文本，并调用模型识别姓名、岗位、地点、教育背景、技能和简介。
- 导入完成后自动生成一份初始候选人分析报告；填写职位要求后可继续生成岗位匹配报告。
- 粘贴职位要求，让 Agent 汇总证据、差距、建议追问及辅助评分。
- 分析工作区提供常用任务快捷入口和“优化任务”AI 草案；草案只发送招聘者写的任务文本，预览并确认后才会替换。“联网参考岗位背景”是显式开关，打开后只根据职位要求搜索公开资料，不发送候选人简历。
- 职位要求旁提供 AI 整理岗位重点功能，结果先以草案展示，审核员可采用或保留原文。
- 为领导力、专业能力、经验、经历广度、岗位契合度和进步分生成评分卡；综合分按可调权重加权计算。
- 支持手动修改评分权重，也支持让 AI 提出调整方案；方案会先预览综合分和当前排名变化，由审核员确认后应用；“候选人对比”视图按综合分排名展示多人分项得分。
- 分析文档内置六项能力雷达图、综合分-时间趋势折线图，以及项目拆解卡；支持按需调用 AI 将最多四段经历整理成人话草案，并可点击原文引用定位 PDF。
- 分析文档增加综合分贡献拆解：同时显示单项分数、权重、实际贡献值和证据置信度，便于解释综合分来源。
- 点击评分历史中的证据句子可以回到 PDF 原文并定位高亮；无法精确匹配时会明确提示，不使用模糊匹配冒充证据位置。
- 分析报告会把当前候选人与本地历史同岗位样本比较，显示“超过历史样本 X%”的百分位标记，并展示首轮通过线、录取线和样本通过率；从报告可打开预先筛选到当前岗位族和年份的历史样本库，且保留已点选样本。
- 内置多份产品、运营、数据、前端、后端和用户研究示例简历，便于直接体验多人对比和招聘质量图。
- 招聘质量图默认展示能力深度 × 经历广度，也可手动选择不同能力作为横纵轴；象限分界可在 20–80 分间调整，区域面积和文字标注会随分界移动，点击象限会联动筛选候选人排名表。多人对比 AI 可按自然语言同时调整评分来源、排名、图表维度、分界和象限，方案确认后才生效。
- 新增资料库入口，支持查询、增改和删除本地竞赛、期刊 / 会议及公司资料；删除前会提示受影响的简历引用，详情中的引用可跳回 PDF 命中词；审核员可填写可解释的含金量评分与备注。
- 资料库的人工评分历史按真实时间间隔绘制，点选记录即可回看当时的评分理由、核验状态和证据来源。
- 可选接入 Tavily 网页搜索；分析 Skill 位于 `server/skills/resume-analysis.md`。
- 从 PDF 提取文本或外部 OCR 结果中提取竞赛、论文和项目，调用对应 Skill 联网核查，保存到项目根目录 `db/`，之后优先复用有效缓存。
- 从工作台打开本地简历文件夹，或将已有文件夹中的 PDF 导入工作台。

## 环境要求

- Node.js 20 或更高版本
- npm
- 一个兼容 OpenAI Chat Completions 接口的模型服务及 API Key
- Tavily API Key（可选；不配置时 Agent 不会进行网页搜索）

## 安装和启动

在项目根目录运行：

```powershell
npm install
```

在项目根目录新建 `.env` 文件，并按下一节填写配置。然后启动前端和本地 Agent 服务：

```powershell
npm run dev
```

`npm run dev` 和 `npm run build` 会自动从 PDF.js 复制中文 CMap 与标准字体到本地静态资源目录，无需手动下载。该生成目录已忽略，不会提交到 Git。

Vite 默认地址为 `http://127.0.0.1:5173/`。开发服务器仅监听本机回环地址。首次启动或修改 `.env` 后，请重启 `npm run dev`，让 Agent 服务重新读取配置。

## 环境变量

在项目根目录新建 `.env`，内容格式如下。替换示例占位值，不要把真实密钥放进代码、README 或提交记录。

```dotenv
# 必填：模型服务 API Key
OPENAI_API_KEY=your_model_api_key

# 可选：OpenAI 兼容服务的 API 根地址。
# 官方 OpenAI 服务使用默认值；第三方服务请填写服务商给出的 /v1 地址。
OPENAI_BASE_URL=https://api.openai.com/v1

# 必填：模型服务中实际可用的模型名称
OPENAI_MODEL=gpt-4.1-mini

# 可选：Tavily 搜索 API Key；可在 https://app.tavily.com/ 获取
TAVILY_API_KEY=your_tavily_api_key

# 可选：本地 Agent API 端口，默认 8787；开发前端代理会自动跟随此端口
PORT=8787

# 可选：简历文件夹。相对路径以项目根目录为基准；默认 .data/resumes
RESUME_DIR=.data/resumes
```

### 模型服务配置

`OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL` 必须对应同一个服务商账号和服务端点。`OPENAI_BASE_URL` 应是 API 根地址，应用会调用其 Chat Completions 接口。若使用 OpenAI 官方服务，可使用上面的默认地址；若使用兼容服务，请按服务商文档填写地址和模型标识。模型需要支持 Chat Completions、工具调用以及简历信息提取所需的普通对话请求。

### Tavily 搜索配置

从 Tavily 控制台创建 API Key 后填入 `TAVILY_API_KEY`。配置为空时，模型分析仍可使用，但网页搜索不可用。配置非空时，Agent 会在认为有助于回答时调用搜索工具；简历分析 Skill 限制搜索内容为职位相关公开信息，不允许借搜索调查候选人的敏感或私人信息。

## 简历文件夹和 PDF 导入

默认目录为项目根目录下的 `.data/resumes/`。每个导入的 PDF 会复制到此目录，候选人元数据保存在其 `.metadata/` 子目录。`.data/` 已加入 `.gitignore`，简历文件不会被 Git 跟踪或推送到 GitHub。

侧栏的“导入 PDF 简历”用于选择一个或多个文件；“导入文件夹”可选择一个已有目录并导入其中的 PDF；“打开存储位置”会在本机文件管理器中打开工作台自己的简历目录。也可以把 PDF 放入 `RESUME_DIR` 指定的目录，再刷新工作台，由服务扫描并索引新文件。

文本型 PDF 会提取文字，并尝试由模型识别候选人基本信息。扫描件或图片型 PDF 仍可在阅读器中查看，但当前版本没有 OCR，因此无法从纯图片页面提取文字或据此分析。请人工核对模型提取的信息和分析结果；评分仅作参考，不应单独作为招聘决定。

## 评分与候选人对比

默认评分权重为：领导力 18%、专业能力 24%、经验 20%、经历广度 10%、岗位契合度 23%、进步分 5%。综合分公式为 `Σ(单项分数 × 权重) / Σ权重`，服务端会将手动输入或 AI 建议的权重归一化为 100%。AI 建议不会直接保存；审核者可先看六项权重变化、当前候选人的综合分变化和同岗位族排名变化，再选择应用或丢弃。示例档案会在预览中单独计数。导入 PDF 或重新分析时，分析报告与评分卡并行生成以减少等待；两项都成功后才保存，综合分始终由服务端计算。多人对比表以数值条辅助横向比较；点击候选人的证据摘要可回到简历分析并尝试在 PDF 原文定位。

多人对比页可按“已生成评分卡”或“演示 / 待评分”筛选，筛选会同时作用于质量图和排名表；两类记录数量始终可见，避免把演示分误当真实评估。分项得分旁显示模型对现有证据充分度的置信度，低于 45% 时以提示色标出；点击任一分项分数会选中候选人并定位到对应证据卡，卡片内的证据可继续跳回 PDF。置信度不是录用概率，也不保证统计校准。排名依据可切换为综合分或任一能力分数，招聘质量图的点内数字对应表格名次，选中候选人时显示姓名；气泡半径固定映射综合分 0–100，图例给出 50 / 100 分参考大小，不随当前最高分改变缩放。坐标相同或接近时，点可能重叠，可直接点下方候选人行选择。也可输入自然语言让 AI 同时建议评分来源、排名维度与顺序；方案先预览再应用，只改变当前展示，不会修改评分、权重或候选人数据。
对比表逐项标记是否为真实保存的评分卡；没有评分卡的演示简历或未完成评分的档案会使用演示分，并在对比页明确计数，避免把演示结果当作真实评估。

“经历广度”只评价与工作相关的行业、领域、方法和团队经历，不使用性别、民族、年龄、国籍、残障、宗教、婚育等受保护属性。评分卡保存于候选人的 `.metadata/<id>.json`，当前权重保存于 `.metadata/settings.json`。分析文档会显示综合分和六项评分；点击能力雷达图的顶点 / 标签或贡献拆解条目，可以查看单项评分依据，再点击依据回到 PDF 尝试定位原文。顶部“候选人对比”可查看所有候选人的分项得分和排名。

分析任务旁的“优化任务”可将审核者的自由描述整理成清晰的 Agent 指令。该请求只包含当前任务文本，不发送简历、候选人姓名或职位要求；返回草案后可预览、采用或保留原文。该操作是可选的额外模型请求，直接编辑或使用快捷任务不需要先优化。

“联网参考岗位背景”默认关闭。打开后，PDF 分析会用职位要求生成有限的公开网页检索，结果只作为岗位背景线索传给 Agent，并在工作区列出来源；它不能证明候选人的个人经历。没有 Tavily 配置或检索失败时，分析仍会继续，并显示降级状态。通用 Agent 也使用同一开关控制工具调用，避免在未明确需要时产生额外搜索延迟。

分析文档的“综合分复评记录”只绘制实际保存的评分结果。点击某个历史点可以查看当次六项分数、证据、岗位要求和评分权重；导入 PDF 时记录初评，之后每次成功复评追加一条历史。示例简历不伪造趋势数据。

项目拆解默认显示规则版，可填写本次 AI 解读侧重点（最多 500 字），例如“用非技术语言解释，重点说明个人贡献”；点击“AI 人话拆解”只发送当前显示的最多四段经历片段和该侧重点。模型按专用 Skill 分开解释目标、个人行动和结果。AI 结果以草案展示，每条引用必须是至少 6 个字符且与对应经历原文完全一致的片段，点引用可回到 PDF 定位。修改侧重点会清除旧草案；草案不写入简历或评分记录，切换候选人也会清除草案。没有模型配置时仍可使用规则版拆解。

### 历史招聘基准库

`shared/history.ts` 提供本地演示样本；顶部“历史样本”入口可新增、编辑、删除本地样本，并按岗位族和年份筛选。样本管理页新增 0–19、20–39、40–59、60–79、80–100 五档分布，条形长度表示当前岗位 / 年份筛选下的样本数，颜色区分最终录取、仅通过首轮和未过首轮；点击区间或结果图例会联动筛选记录与下方分数轨道，分数段和招聘结果可以组合筛选。还可输入自然语言生成筛选草案，确认后应用；此请求只发送筛选指令、可用岗位族和年份，不发送历史样本记录。样本图中的点与记录列表也互相联动；结果轨道标有该组样本量，分析报告中的首轮参考线样本量统计全部首轮通过者（包含最终录取者），而分布轨道将“首轮通过未录取”单独列组。本地维护数据写入 `.data/resumes/.metadata/history-candidates.json`，不会推送到 GitHub。系统只存匿名代号、岗位、年份、综合分和首轮 / 录取结果，不存历史简历正文。分析报告中的分布图按岗位族计算百分位，只统计综合分严格低于当前分数的历史记录，例如“超过历史样本 67%”表示 67% 的同口径样本分数更低，同分记录不计入超过比例。若当前岗位族没有样本，卡片会标明使用“全部岗位族”作为回退口径，打开样本库也会沿用相同筛选；没有录取或首轮通过样本时，对应参考线显示暂无该类样本；样本少于 10 份时，报告提示百分位和参考线容易受单条记录影响。结果参考线按对应结果组综合分的中位数计算，偶数样本取中间两数的平均值并保留一位小数。百分位与结果中位数是辅助比较，不是录用规则。种子记录为虚构演示数据；正式使用前应导入经授权和脱敏的汇总结果。

实际部署时应将种子数据替换为经过授权和脱敏的招聘记录，并保留样本年份、岗位口径和评分版本，避免把不同岗位或不同评分标准直接混在一起比较。

### 竞赛、期刊与公司资料库

评分档位同时显示各档总条目数、已保存人工评估数和待评估数，避免将内置演示值误读为审核员结论；点击评分档位可按分值筛选，点击图例可筛选人工已评或待评资料，并与其它筛选组合。
资料自然语言筛选也能区分“已有人为评估”和“待评估”；这与资料本身是否核验是两个独立状态。通过简历交叉引用打开资料时，筛选会自动重置，保证目标记录可见。

顶部“资料库”入口打开本地资料查询工作区。资料支持按类别、核验状态、人工评分区间、来源覆盖状态和是否被简历引用筛选，支持关键词搜索和按名称、评分或更新时间排序；列表会显示每条资料被多少份简历引用。分类分布、评分分段和来源覆盖图均可点击并与列表联动；核验均分只统计已核验条目。列表支持自然语言筛选，AI 草案会明确显示筛选维度和预计命中条数，经审核员确认后应用；请求只发送指令，不发送候选人简历或资料记录。每条资料可记录最多 12 个来源及其类别、数据年份、说明和人工核对状态；修改来源身份信息会自动撤销原核对标记。人工评分可以引用来源，评分历史会保存当时选择的来源并允许再次打开。审核员也可以给 AI 提供岗位背景和自然语言评估侧重，例如优先核对官方赛果、降低宣传材料权重。AI 建议会先作为独立草案展示分差、理由、置信度和核验问题；审核员确认采用后才会填入评分表，之后仍需点击保存。评估侧重不能覆盖证据规则。搜索不可用时会明确标注降级状态。联网核验只发送资料条目的名称、领域和组织，不发送候选人简历。示例数据位于 `shared/knowledge.ts`；自定义资料和人工评估保存在 `.data/resumes/.metadata/`，不会提交到 GitHub。

资料库支持将自建条目、内置资料的人工评估历史和来源快照导出为 JSON，也支持先预览、再确认的批量导入；同 ID 自建条目会更新，其它现有记录保留。内置资料正文只读，备份可恢复其人工评估和核验记录，不覆盖内置资料正文；旧版仅含自建资料的备份仍可导入。详细格式与限制见 [`docs/KNOWLEDGE_DATABASE.md`](docs/KNOWLEDGE_DATABASE.md)。

资料库目前有 230 条内置记录：竞赛 122 条、期刊 / 会议 100 条、公司 8 条。原始 23 条示例与整理目录中相同的条目已合并，保留原 ID 和人工评估关联。未人工评估的目录资料不显示推断分数；旧示例分数仅为待审核的起始值，不是权威排名。完整字段、类别审核要点和维护边界见 [`docs/KNOWLEDGE_DATABASE.md`](docs/KNOWLEDGE_DATABASE.md)。

资料库概览新增“审核准备度”流程统计，可点击“待补来源 / 待核来源 / 待人工评估 / 已完成”直接筛选资料。该指标描述资料是否具备审核条件，不代表资料含金量；AI 也能识别这四种状态，预览精确匹配数量后应用同一阶段筛选。

资料库 API 为 `GET /api/resumes/knowledge`、`POST /api/resumes/knowledge`、`POST /api/resumes/knowledge/enrich`、`POST /api/resumes/knowledge/filter-draft`、`PUT /api/resumes/knowledge/:id`、`PUT /api/resumes/knowledge/:id/review` 和 `POST /api/resumes/knowledge/:id/suggest`。资料草案、评分建议和列表筛选分别使用 `server/skills/knowledge-enrichment.md`、`server/skills/knowledge-assessment.md`、`server/skills/knowledge-filter-assistant.md` 约束；资料草案只填充未保存表单，评分建议等待人工确认，自然语言筛选只返回经校验的列表条件。Tavily 返回的网页摘要只是检索线索，系统不宣称已独立核实网页内容。通用 Agent 与资料核验共用搜索适配器，对相同查询短时缓存、合并并发请求；失败不缓存。分析报告和资料详情支持双向跳转；引用仅由简历中出现的资料名称或别名确定性匹配，不代表已核实。示例评分只用于演示界面和审核流程，使用真实招聘时应核对官方来源、具体名次、作者贡献、岗位职责和项目结果。

## 数据与隐私

- `.env`、`.env.*`、`.env.example` 和 `.data/` 均被 Git 忽略。项目不会提供可提交的密钥模板；请在本机创建 `.env`。
- 简历 PDF 和提取文本保存在本机 `RESUME_DIR`，不会因为导入操作自动上传到 GitHub。
- 导入 PDF 时，提取出的简历文本会发送给 `.env` 中配置的模型，用于整理候选人基本信息。用户主动运行分析时，简历文本、职位要求和提问也会发送给模型服务。
- 若 Agent 调用 Tavily，发送给搜索服务的是搜索查询和搜索请求，不会自动上传整份 PDF。
- 开启成果核查时，简历文本会额外发送给模型提取成果条目，再将成果名称、年份、机构等线索交给检索流程；成果报告保存在本机 `db/`，已加入 Git 忽略规则。关闭“核查竞赛、论文和项目资料”可跳过这一步。
- 请确认你的模型和搜索服务的数据处理方式符合组织的招聘、隐私和数据保留要求。

## 竞赛、论文和项目资料核查

分析区默认勾选“核查竞赛、论文和项目资料”。点击分析后，服务先从简历文本中提取输入，附带连续原文证据，再查询 `db/`；缓存未命中且配置了 `TAVILY_API_KEY` 时，使用对应 Skill 搜索并读取网页正文，生成符合原模板的六块 JSON。界面实时显示提取、核查、生成分析的阶段、已用时间和完成项数；每项完成即展示资料，可展开查看原文证据、来源和完整报告。“停止分析”、切换候选人或关闭页面会取消后台模型与网页请求。

核查默认同时处理两项，每项最多 90 秒，整个资料提取与核查阶段最多 180 秒；到达时限后保留已完成资料，将剩余条目标为失败并继续基本简历分析。模型分析阶段最多 120 秒，正文随模型返回逐段显示，整个分析请求最多 300 秒。提取和研究阶段每次模型请求默认 60 秒且不自动重试，最终分析请求遵循分析阶段时限；网页请求最多 15 秒。超时、断线会明确显示错误并保留已收到的正文，避免持续转圈。首次检索仍可能需要数分钟，速度受配置的模型和成果数量影响。

可在本机 `.env` 中按需调整下列配置，修改后重启服务：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `OPENAI_EXTRACTION_MODEL` | 跟随 `OPENAI_MODEL` | 提取成果所用模型，可填写服务商支持的较快模型 |
| `OPENAI_RESEARCH_MODEL` | 跟随 `OPENAI_MODEL` | 成果检索所用模型 |
| `MODEL_REQUEST_TIMEOUT_MS` | `60000` | 每次模型请求超时，毫秒 |
| `WEB_REQUEST_TIMEOUT_MS` | `15000` | 每次网页请求超时，毫秒 |
| `RESEARCH_ITEM_TIMEOUT_MS` | `90000` | 单项成果核查上限，毫秒 |
| `RESEARCH_TIMEOUT_MS` | `180000` | 提取与核查总时限，毫秒 |
| `ANALYSIS_TIMEOUT_MS` | `120000` | 最后生成分析阶段的总时限，毫秒 |
| `AGENT_TIMEOUT_MS` | `300000` | 整个分析请求总时限，毫秒 |

| 类型 | 提取的 skill 输入 | 可缺省 |
| --- | --- | --- |
| 竞赛 | `competition_name`、`award_name`、`award_year`、`age_at_award` | 获奖年龄；只保留原文明确写出的获奖时年龄，不计算、不用于评价 |
| 论文 | `title`、`description`；已提供的作者、年份、DOI 等映射到 `extra_context` | 描述和额外线索 |
| 项目 | `project_name`、`project_year`、`organization`、`role` | 角色；年份区间保留原文 |

缺少检索所需的名称、年份或所属机构时，保留 `null` 并提示待补充，不借用无关教育或工作信息。竞赛组别、赛区、阶段、论文版本等原文线索参与检索和缓存匹配；年龄不参与缓存匹配。系统采用保守的精确匹配，不自动合并简称或同名成果。

扫描件仍需外部 OCR：在“补充 OCR 文本”中粘贴识别结果后，它将替代本次分析的 PDF 文本；切换候选人会清空补充内容。此功能没有新增扫描件 OCR 引擎。

也可以直接调用 API，`text` 支持 1 到 100000 字符：

```http
POST /api/research/extract
Content-Type: application/json

{"text":"这里填写简历的 PDF 提取文本或 OCR 结果"}
```

`/api/research/extract` 只提取，返回 `{items, notes}`；每条包含 `kind`、`input`、`context`、`evidence`、`missingFields` 和 `notes`。`POST /api/research/enrich` 使用相同输入，额外查询数据库并检索，返回 `{items, notes}`，每条包含 `item`、`status`、`report` 和 `error`。`POST /api/agent` 支持可选布尔字段 `includeResearch`（默认 `true`），结果额外返回 `research`。传入 `streamProgress:true` 时，响应为 `application/x-ndjson`，逐行推送 `progress`、`research`、`answer`、`heartbeat`、`complete` 或 `error` 事件；`answer.text` 是生成中的正文片段，`answer.replace:true` 表示重置当前草稿。未传入时仍返回原有 JSON 响应。

未配置 Tavily 时仍会提取条目并查询已有缓存，未命中条目标为待补充，不声称完成联网核查。所有提取和生成都需要模型服务。来源必须是网页工具本次实际读取的正文；未知事实填 `null`，缺口写入 `notes`。身份或年份未确认的报告保存但不作为后续缓存命中。缓存默认有效 30 天，过期重查、保留旧版本，具体布局见 [db/README.md](db/README.md)。现有目录外的旧报告不会自动导入。

竞赛与项目 Skill 采集事实，不计算含金量；论文 Skill 按可核实的发表渠道、年份和轨道给出有限评价。公共资料无法证明简历持有人的实际获奖、署名、参与或个人贡献，分析时与简历自述分别处理。

## 期刊会议目录数据

`papers.md` 已导入 `db/papers.json`，保留 55 个会议、45 本期刊的全部字段，含分级体系、版次、年份、等级、适用范围、证据页码、来源读取方式及整理日期。七条重合的原有资料保留旧 ID 合并，期刊会议总计 100 条。更新文档后运行 `npm run import:papers`，导入会校验字段、重复项及 HTTP(S) 来源，并保存源文件 SHA-256。

资料库的“期刊 / 会议”分类支持名称与别名搜索、期刊 / 会议类型、研究领域、分级版本、等级与简历引用筛选。详情保留官网、组织出版背景、介绍、影响力、难度、来源和匹配注意事项，并连接原有人工评估入口。简历初始报告、岗位报告和 AI 分析可读取匹配的本地渠道背景；通用学科名称和易混淆短名需要明确的发表渠道上下文。

分级保留各自体系和适用年份，不换算 A/B/C 与 T1/T2/T3，不将当前目录套用于历史论文；主会、Workshop、Findings 及文种需另行核验。年度指标和完整收录信息保持 `null`（未核验）。渠道名称命中不证明论文正式发表或候选人贡献，也不替代按论文标题查证的研究报告。

简历核查发现目录中没有的赛事或期刊会议时，系统会在联网核查完成后用已读取的公开来源生成标准资料条目，写入 `db/library/` 并在分析结果中提示“已整理为标准条目”。同名条目会去重；来源只读到搜索摘要、主体无法确认或字段不足时不会写入，只显示待补充。自动条目仍是待人工核验资料，不会自动给出含金量分；刷新资料库即可查看。
