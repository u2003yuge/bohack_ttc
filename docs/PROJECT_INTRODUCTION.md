# Bohack：有材料依据的 AI 招聘简历工作台

Bohack 面向 TTC“AI 赋能招聘与人才挖掘”的深度简历解析方向。招聘人员可以导入 PDF，阅读原始简历，收集竞赛、论文和项目背景，将每项经历拆成可解释的材料，再根据候选人亲自完成的行动派生五维能力，最后按具体岗位偏好比较候选人。

## 一次完整使用流程

1. 导入单份、批量 PDF 或文件夹，文件与候选人数据保存在本机。
2. 在默认的“材料评分”入口评估简历。可选择 AI 提取材料；没有模型配置时，也能使用保守规则抽取。
3. 对竞赛、论文和项目查询本地成果资料库，必要时调用三个搜集 Skill 联网补充。报告保留年份、范围、来源及缺口；没有官方数据不会自行推算。
4. 查看材料卡：材料分、因素权重、覆盖率、待补信息、个人行动映射，以及可点击的原文或外部来源。
5. 查看专业执行、问题解决、责任与交付、协作与组织、学习与研究五维画像。每个分数都能拆解到具体材料和递减权重。
6. 在“岗位排序与对比”中选择岗位预设，手动调整权重，或输入“更看重独立交付和问题解决，必须 Python”等偏好。预览草案及排名变化后采用，可以保存岗位配置。
7. 对比候选人、回看复评记录，或导出包含规则、来源和输入快照的评分 JSON。

内置林澈、周宁、许远三份明确标注的合成验收简历，分别展示完整个人行动、普通项目的明确贡献、团队成果缺少个人分工三种情况。演示档案只按合成原文计算，不检索虚构背景。

## 评分如何产生

```text
简历 + Skill 原始资料
  → 七类材料与实体去重
  → 固定因素规则计算材料分 M
  → 根据个人行动确定 A、按材料类型读取 R
  → D = M × R × A
  → 按“能力维度 × 材料父类型”分别排序和递减
  → 五维能力 P
  → 按当前岗位 q 计算排序分
```

材料类型包括奖项、研究、项目、工作实习、专利、开源作品和证书课程。模型负责提取事实与原文，评分函数由代码计算；AI 文字报告解释同一份计算结果，不再独立打一个人物总分。

积分允许超过 100，不把未知记成零。团队项目可以有较高材料分，但没有个人行动证据时，不会自动产生人物能力分。资料核查、候选人贡献和因素覆盖分别表达，不合成所谓“可信度乘数”。同一成果重复出现会合并来源；不同年份的独立成果保留，同类贡献以 `ρ=0.5` 递减。

首版工程开发岗权重依次为 35%、25%、25%、10%、5%；研究算法岗为 20%、25%、10%、10%、35%；团队管理岗为 15%、15%、25%、40%、5%。完整七类材料因素权重、适配矩阵和行动档位见 [SCORING_V1.md](SCORING_V1.md)。岗位偏好变化只影响排序，基础材料分和能力分不变。

没有岗位名称、所需能力为 NA、必备条件尚未核实或存在冲突时，不强制生成可比总分。符合、明确不符合、未找到证据和来源冲突分别显示。历史六维分数与历史招聘样本继续作为历史资料查看，不能与新评分直接比较。

## 项目组成

| 部分 | 负责什么 |
| --- | --- |
| React + TypeScript + Vite | 简历库、PDF 阅读、材料卡、五维图、岗位偏好及候选人对比 |
| Express 本地 API | 导入、分析编排、流式进度、停止请求和数据保存 |
| PDF.js | 中文 PDF 文本提取、原文阅读和证据定位 |
| `server/skills/` | 三类资料搜集 Skill、材料抽取和岗位偏好指令 |
| `server/research/` | 搜索、正文读取、报告校验、缓存和重复请求合并 |
| `shared/material-scoring.ts` | 七类因素、具体权重、五维矩阵、行动系数、递减与排序 |
| `server/scoring/` | 材料适配、证据校验、评分编排、偏好解析和 API |
| `db/` | 公共成果背景 JSON 及 30 天有效缓存，保留报告历史 |
| `RESUME_DIR/.metadata/` | 私有候选人材料、评分历史和岗位配置 |

评估保存规则版本、SHA-256 输入指纹、原始输入、来源报告和规则快照。岗位配置独立保存；并发复评会保留各次历史，候选人文件采用临时文件与原子替换保存。

## 启动与验收

```powershell
npm install
npm run dev
```

浏览器打开 Vite 地址。模型及搜索配置沿用 README 中的 `.env` 说明；不配置模型也可以体验材料规则评分，AI 提取、联网核查及 AI 文字报告需要相应服务。扫描件可以粘贴外部 OCR 文本，目前没有内置 OCR 引擎。

```powershell
npm test
npm run build
npx tsc --noEmit --project tsconfig.server.json
```

30 条合成材料位于 `shared/scoring-samples.ts`，双人标注表位于 [SCORING_ANNOTATIONS.csv](SCORING_ANNOTATIONS.csv)。当前参数是可执行的初版假设，尚未宣称完成双人评审或招聘结果校准。规则抽取偏保守，复杂同名成果、论文版本关系、个人角色和年限要求仍可能需要补充原文或人工核实。
