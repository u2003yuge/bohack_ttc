# 简历 Agent 流程拆分

本系统将简历解析和分析拆为职责单一的 Agent。每个 Agent 有固定输入、输出和依赖；编排器按请求补齐缺失依赖，并用 SHA-256 输入指纹复用已有结果。候选人文本或相关参数变化时，只会使使用这些字段的 Agent 失效。

## Agent 清单

| Agent | 单一职责 | 主要输入 | 输出 | 依赖 |
| --- | --- | --- | --- | --- |
| `candidate-profile` | 提取姓名、岗位、地点、教育、技能、摘要 | 简历全文、文件名 | 候选人基础字段 | 无 |
| `material-extraction` | 识别竞赛、论文、项目、工作、专利、开源、课程等材料，并保留简历原文与个人行动证据 | 简历全文、材料抽取模型开关 | 结构化材料、抽取模式、缺口说明 | 无 |
| `competition-research` | 为竞赛和奖项查本地库；必要时由竞赛 Skill 搜索并读取公共资料 | 奖项材料、简历原文 | 竞赛身份、年度背景、来源和核查状态 | 材料抽取 |
| `paper-research` | 核对论文身份、发表状态、渠道及可用来源 | 论文材料、简历原文 | 论文报告、渠道资料、来源和核查状态 | 材料抽取 |
| `project-research` | 核对项目、组织及公开项目背景 | 项目材料、简历原文 | 项目报告、组织资料、来源和核查状态 | 材料抽取 |
| `achievement-research` | 合并三类成果核查结果，提供稳定的统一下游格式 | 竞赛、论文、项目核查结果 | 统一 ResearchBatch | 三类成果核查 |
| `evidence-annotations` | 把材料证据关联回原文，并导出可定位片段与外部来源跳转信息 | 抽取材料、核查结果 | 类型、原文、文本偏移量、核查状态、来源链接 | 材料抽取、成果核查 |
| `score-calculation` | 按版本化固定规则计算材料分和能力维度，不让模型提供分值 | 材料、核查事实、评分规则版本 | 完整 Assessment 与证据快照 | 材料抽取、成果核查 |
| `analysis-report` | 根据候选人字段生成初始报告，或根据岗位要求生成岗位分析 | 简历全文、候选人字段、岗位要求、用户问题 | 分析报告文本 | 候选人信息提取 |
| `plain-language-breakdown` | 将项目/工作原文拆成目标、行动、结果和通俗标题 | 项目/工作材料、审核重点 | 可逐项回溯的项目拆解 | 材料抽取 |

材料抽取是下游证据、评分和项目拆解的共同基础；三类成果核查分别只消费对应材料，汇总节点不调用模型或搜索；评分依赖抽取和成果核查；报告生成独立于评分，不会因为改报告任务而重算分数。证据标注和跳转链接也不参与评分。编排器按依赖层调度：候选人信息提取与材料抽取并行，竞赛、论文和项目核查并行，证据标注与规则评分并行；同层 Agent 互不等待，只有真正存在依赖关系的下一层才会等待。每个 Agent 完成后立即发出流式章节，前端可以逐项展示，不必等同层其它 Agent 完成。

PDF 首次导入已通过同一编排器运行候选人信息提取和规则评分，并在模型可用时生成初始报告。导入阶段将 `includeResearch` 设为 `false`，不触发联网或本地成果背景核查；后续可按需单独运行对应核查 Agent。

## 调用与增量更新

`GET /api/agents/catalog` 返回 Agent 名称和依赖。对已导入候选人使用 `POST /api/resumes/:id/agents/run`：

```json
{
  "agents": ["plain-language-breakdown"],
  "reviewerFocus": "用非技术语言解释项目解决的问题"
}
```

仅项目拆解时，服务端复用已保存的材料抽取结果；如果缓存缺失或输入指纹失效，只先重跑材料抽取，再执行项目拆解。只改分析问题或岗位要求时，只重跑报告 Agent。显式请求 `score-calculation` 时，才会在评分重算成功后追加评估历史。也可以请求多个 Agent，例如同时更新报告和证据标注；它们共享需要的依赖输出。

Agent 运行结果保存在简历元数据的 `agentArtifacts`，每项包含 Agent ID、输入指纹和输出。缓存按下列语义失效：

- 简历文本变化会使候选人提取、材料抽取及其后续材料依赖任务失效。
- 文件名只影响候选人信息提取。
- 岗位要求和用户问题只影响分析报告。
- 审核重点只影响项目人话拆解。
- Tavily、模型或研究模型配置变化影响对应类别的成果核查；材料变化时只使包含变化材料的类别核查失效，未变化类别可复用。
- 评分仅依赖材料与核查结果；报告偏好变化不触发评分。
- `force: true` 只强制重跑本次明确请求的 Agent，其未显式请求的依赖仍按输入指纹复用。

Agent 定义版本通过 `agentVersion` 指纹盐单独维护。提示词、输出结构或确定性算法产生不兼容变化时，应递增相应 Agent 的版本，旧缓存便会自然失效。配置变化若影响输出，也必须加入该 Agent 的指纹输入。

## API

- `GET /api/agents/catalog`：读取可调用 Agent 和依赖关系。
- `POST /api/agents/run`：无候选人档案时以请求中的简历文本运行所选 Agent；调用方负责保存返回的 `artifacts`。
- `POST /api/resumes/:id/agents/run`：读取档案文本、运行所选 Agent，并把产物和被更新字段持久化到本地候选人元数据。

两种运行入口都接受 `agents` 数组，以及可选的 `roleRequirements`、`question`、`reviewerFocus`、`force`、`useModel`。响应的 `executed` 和 `reused` 可用于审计本次实际调用范围。取消、输入过长、Agent 失败或依赖缺失时不写入部分结果。

### 流式报告

分析入口传入 `streamProgress: true` 时使用 NDJSON。每个 Agent 完成后立即发送一个 `agent` 事件，其中包含该 Agent 的 Markdown 章节；前端收到后立刻追加到分析文档，不等待整条流程结束。`progress` 事件只描述当前阶段，`complete` 事件再补充最终保存的候选人档案。资料核查完成时另外发送 `research` 事件，便于先显示已完成的资料结果。

简历分析链路不包含置信度计算 Agent，也不包含人工审查 Agent。评分只由固定规则根据已提取材料计算；报告 Agent 只解释已有证据，不生成置信度或审查结论。资料库的人工资料评估属于独立功能，不会插入简历分析链路。

## 边界与后续

成果研究报告描述竞赛/论文/项目的公共背景，不能证明候选人个人获奖、署名或贡献。评分 Agent 消费可定位的简历行动证据和研究资料，但能力分仍由固定规则计算。报告生成只解释证据，不覆盖评分结果。

新增功能应先定义独立输入/输出和缓存指纹，再登记 Agent；若功能只改变某个 Agent 的输入，不应扩展成整条流水线重跑。对共享模型调用增加超时、取消和并发限制时，应复用 `server/operations.ts` 中的现有约定。
