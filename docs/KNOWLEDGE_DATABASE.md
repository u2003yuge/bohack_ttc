# 竞赛、期刊与公司资料库

资料库是招聘工作台中的独立查询入口，用来保存候选人简历中出现的竞赛、期刊 / 会议和公司背景资料。它提供背景信息和人工审核记录，不能把名称或平台宣传直接当成候选人的个人成果证明。

## 竞赛资料目录

`competitions.md` 的 118 条赛事资料已完整导入 `db/competitions.json`。使用 `npm run import:competitions` 重新生成；脚本先校验字段、重复 ID / 名称和 HTTP(S) 来源，再写入文件，并保留来源 SHA-256。所有原始字段均保存，包括 `name`、`category`、`official_website`、`organizer`、`short_info`、`info`、`influence`、`difficulty`、`acquires`、`projection`、`sources`，以及原始 ID、目录年份和备注。

共享模型 `shared/competitions.ts` 将目录映射到既有资料模型的 `competition` 字段。与原有 ICPC、挑战杯学术科技作品赛、中国国际大学生创新大赛、蓝桥杯四条资料合并时保留旧 ID 和别名，已有人工评估仍按原 ID 关联。两个目录合并后内置 230 条资料，其中竞赛 122 条（118 条详细目录 + 4 条其他原有竞赛）、期刊 / 会议 100 条、企业 8 条。全国大学生数学建模竞赛不与 COMAP 数学建模赛事合并。

页面默认进入独立的竞赛板块，期刊 / 会议和企业通过顶部分类切换。竞赛列表支持多关键词、学科领域、目录年份和简历引用交叉筛选；详情展示介绍、影响力、难度、能力要求、素质、官网及全部来源，原有人工评估和资料管理通过详情入口访问。导入背景不生成评分，未保存人工评估时主页面显示“待人工评估”。

`GET /api/resumes/knowledge?kind=competition` 可单独读取竞赛数据；省略 `kind` 兼容原有完整列表。导入目录为基础资料，人工评估仍写入本地 `.metadata/knowledge-reviews.json`，备份保留目录 ID 对应的人工评估历史。自建竞赛备份如携带 `competition` 详细字段，导入时验证并保留这些字段。

简历初始报告、岗位报告与流式分析会按简历中出现的名称 / 别名读取本地赛事背景和来源，无需再次搜索这些基础介绍。固定目录不替代按候选人获奖年份、奖项和赛道生成的核查报告；目录年份不等于获奖年份或来源网页年份，影响力与难度描述不转化为自动分数。

## 期刊会议资料目录

`papers.md` 的 100 条资料已完整导入 `db/papers.json`，含 55 个会议和 45 本期刊。运行 `npm run import:papers` 校验并重新生成；源 Markdown 随项目保存，数据库含来源 SHA-256。`shared/venue-profile.ts` 定义字段与导入校验，`shared/venues.ts` 将资料映射到既有记录的 `venue` 扩展字段。原有 Nature、TPAMI、NeurIPS、CVPR、ACL、IEEE TSE、KDD 七条资料保留旧 ID、别名和人工评估关联；期刊与会议仍属于 API 的 `journal` 分类，`venue.type` 区分两种渠道。

期刊会议有独立列表与详情，支持关键词、类型、研究领域、分级体系及版次、目录等级和简历引用交叉筛选。分级筛选要求体系与等级在同一分级条目中匹配，不把 A/B/C 与 T1/T2/T3 换算；未登记分级可单独筛选，不能理解为低质量。详情保留全部分级元数据、来源页码、来源读取方式、整理日期、定性介绍、影响力、难度和备注。`annual_metrics`、`indexing` 保持 `null`，页面显示未核验。

`GET /api/resumes/knowledge?kind=journal` 返回这 100 条渠道；人工评估仍使用原接口和磁盘记录。备份恢复支持已知内置 ID 对应的评估历史；自建资料备份的有效 `venue` 扩展字段保留嵌套分级及来源信息，拒绝不安全网址或不符合当前模式的元数据。

初始简历报告、岗位报告与流式分析可读取匹配的本地发表渠道背景，并带来源、适用年份及匹配提示。通用学科名称（如 Computer Science）和易混淆短名需要明确的发表渠道上下文，避免将教育专业或技能误认成期刊；名称命中仍只是线索，不确认论文身份。渠道背景不替代按标题、发表状态、文种、轨道和个人贡献进行的论文核查。来源中的“全文读取 / 检索缓存”以及 `checked_on` 来自整理者，应用导入时没有重新联网，也不会自动标为人工已核验。

## 未知条目的自动入库

简历核查会额外提取原文明示的竞赛名称和论文发表渠道名称。已有标准条目只返回命中；未命中且联网服务可用时，系统通过独立的标准化流程检索并实际读取公开来源，生成 `competition` 或 `venue` 标准扩展字段，写入 `db/library/custom-auto-<kind>-<sha256>.json`。竞赛按赛事系列保存，期刊会议按渠道保存，不把候选人的奖项、论文题名、作者或个人贡献写入公共条目。

自动条目需要主体确认、官方或可靠来源正文、HTTP(S) 来源和完整字段；来源只有搜索摘要、官网未读、简称有歧义或模型无法确认时不会落盘。每个条目标记 `origin.type=discovered` 和整理时间，初始为待人工核验，含金量评分只是旧表单兼容占位。写入使用锁、临时文件和内容 ID，重复简历或并发请求不会覆盖或重复创建。分析结果会列出条目状态（已有、已创建、待补充或失败），前端在分析结束后刷新资料库。

## 当前能力

- 原始 23 条跨领域示例与两个目录合并后共 230 条内置资料，涵盖国内高校常见赛事、计算机与 AI 研究渠道，以及互联网、硬件和新能源企业。条目提供组织官网入口与审核信号；链接用于查找起点，不代表本次已核验。
- 顶部“资料库”入口打开独立工作区，不会覆盖简历阅读器的左侧候选人列表。
- 按类别、名称、别名、领域、组织、地区、简介和审核信号搜索；支持按名称、最近更新和人工评分排序。
- 支持按待核验 / 已核验状态筛选，并可切换“仅看已被简历引用”；列表会显示引用该资料的简历数量。
- 分类概览显示竞赛、期刊 / 会议、公司数量。核验均分只统计状态为“已核验”的条目。
- 分类概览下方提供评分分布（0–49、50–69、70–84、85–100）；每档同时显示总条目数、已有保存评估的条目数和待评估数，条形用不同颜色区分评估覆盖。评分来自内置演示值或当前人工评估，未保存评估的示例分不会被误标成人工结论。点击分段按分值筛选；点击图例可筛选已人工评估或待人工评估记录，并能与类别、来源和分数条件组合。分布覆盖全部资料，不随搜索和其它筛选改变，使用“清除筛选”可恢复完整列表。
- 增加可点击的审核准备度流程：待补来源、待核来源、待人工评估、已完成。准备度按资料入口、已人工核对的证据来源、已保存人工评估与核验状态计算；点击阶段会过滤列表，可继续与类别、关键词和其它条件组合。它只表示资料流程完整度，不表示该竞赛、期刊或公司本身的质量或含金量。AI 自然语言筛选也能识别这四种阶段；预览中的阶段和命中数与应用后的列表一致。
- 从简历分析报告跳转到资料库时，会清空可能隐藏目标资料的筛选状态，并直接选中目标资料；返回后简历原有列表状态不变。
- 增加来源覆盖图，可交叉筛选有来源、有已核来源、暂无来源的资料；旧记录上的官网入口只算“有来源”，不算已核证据。
- 资料列表提供自然语言筛选助手，可组合类别、核验状态、人工评估状态、来源覆盖、评分区间、关键词、简历引用和排序；人工评估状态依据是否有保存后的 `reviewHistory` 判定，与资料核验状态独立。AI 返回可检查草案及预计命中条数，审核员确认后才应用。请求只包含筛选指令，不传递候选人简历或资料记录，草案不能写入数据。
- AI 筛选 skill 使用完整 JSON 模板约束输出，并可直接设置审核准备度。兼容旧模型遗漏 `readiness` 字段的响应，将其视为未限制阶段；不接受枚举外的阶段值。
- 可以新增资料，也可以修订已有资料。别名会参与简历分析中的确定性文本匹配。
- 可将自建资料和人工评估历史导出为版本化 JSON 备份；导入会先在服务端校验并预览新增 / 同 ID 更新数量，只有显式确认后才写入。导入按 ID 合并，不删除未包含的本地条目；内置示例 ID 会被拒绝，自建数据最多 200 条，单个文件不超过 2 MB。
- 每条资料可登记最多 12 个可追溯来源，保留来源类别、数据年份、人工核对状态和说明。支持官网、学校 / 学院文件、数据库 / 目录、出版方 / 主办方等来源；修改名称、网址、类别或年份会自动撤销原有核对状态。仅提供 http(s) 链接，来源链接按外链打开。
- 本地新增资料可从详情页删除；删除前显示将失效的简历引用数，确认后同步删除该条资料的人工评估历史。内置示例资料保持只读。
- 新增 / 编辑表单可调用“AI 整理资料草案”，按资料名称和类别整理别名、领域、组织、地区、简介及审核信号；可附加自然语言整理重点。若配置 Tavily，系统只搜索资料背景，不发送候选人信息。草案展示置信度、搜索来源和待核验项，审核员可选择补全空白项或采用草案字段；该操作只改未保存表单，不建立数据库记录，也不改变评分和核验状态。
- 每条资料都有官方来源链接、审核信号、人工含金量评分、评分理由和核验状态。
- 可填写岗位背景和审核重点，请 Agent 给出带理由、置信度、核验问题及公开来源的建议。建议先以草稿显示，审核员点击“采用建议”后还要再次保存，才会写入历史。
- 资料详情会反向列出命中该名称或别名的简历；简历分析报告也可以跳回对应资料。
- 每次人工评分可以勾选本次引用的来源；保存后写入评分历史快照。点击历史评分点会展示当时的来源标题、类别、数据年份、核对状态和说明，并可打开原始链接；旧版仅存来源 ID 的记录仍会尝试从当前资料解析。
- 评估历史按 `updatedAt` 时间正序展示，折线横坐标按实际经过时间线性映射，不按记录序号等距绘制；若记录时间相同则退回等距布局，避免数据点重叠。点击数据点继续查看该次评分快照。

## 评分边界

内置评分仅是演示用的待审核起始值，不是权威分级或统一的全国含金量排名。新增资料默认待核验；审核员应结合岗位、届次 / 年份、赛道、候选人贡献和可追溯证据重新评估，并写明理由。不同类别不可只按数字横向比较。审核时应保留以下信息：

- 竞赛：主办方、届次、赛区 / 赛道、参赛规模、获奖层级、结果公示和学校或学院认定文件。
- 期刊 / 会议：ISSN、数据库、指标体系和数据年份、文章类型、正式发表状态、作者贡献以及是否为 workshop 或 poster。
- 公司：具体团队和业务阶段、候选人的职责边界、项目结果、个人贡献和可验证材料。

Tavily 返回的标题、链接和摘要只是检索线索。系统不会据此自动确认网页真实性，也不会把资料背景外推为候选人的获奖、发表或个人贡献。没有足够证据时应保留“待核验”状态。

## 本地存储与接口

示例资料位于 `shared/knowledge.ts`。运行时自定义数据默认写入：

```text
.data/resumes/.metadata/knowledge-records.json  # 新增或修订的资料
.data/resumes/.metadata/knowledge-reviews.json  # 人工评分和审核历史
```

`.data/` 被 Git 忽略，简历和审核数据不会提交到 GitHub。自建资料中的来源随 `knowledge-records.json` 保存；评分历史同时保存引用来源 ID 与来源快照。快照保证资料条目后续被修改或删除时，旧评分仍能显示当时的来源标题、链接、类别、数据年份、说明及核对状态；旧版仅有 ID 的历史仍会尝试从当前资料中解析。当前服务端接口为：

导出文件的格式标识为 `bohack-knowledge-library`、版本为 `1`，包含 `records` 数组和可选 `reviews` 对象。`records` 只包含自建资料及其评估历史；不包含随代码发布的 230 条内置资料正文。`reviews` 以已知内置资料 ID 为键，仅保存这些内置资料的人工评估历史，迁移时不会覆盖内置资料正文。导入流程先调用 `/knowledge/import/preview` 取得规范化文件和资料、评估历史的新增 / 更新计数，再把预览返回的 `bundle` 交给 `/knowledge/import`。同 ID 自建记录以导入版本更新，内置评估历史以导入版本恢复；文件未包含的本地记录和评估保持不变。旧版只含 `records` 的备份仍可导入。该功能用于备份和迁移；不要将不可信来源的 JSON 当作权威核验材料。

内置资料正文为只读，避免本地修改在代码升级或跨设备迁移时产生隐式丢失；审核员仍可在详情页保存人工评分、核验状态、依据和来源引用。自建资料可以编辑或删除。备份会保留内置评估的最近评分和最多 30 条历史快照，包括评估时引用的来源 ID 与来源快照。

```text
GET  /api/resumes/knowledge
GET  /api/resumes/knowledge/export
POST /api/resumes/knowledge/import/preview
POST /api/resumes/knowledge/import
POST /api/resumes/knowledge/filter-draft
POST /api/resumes/knowledge
PUT  /api/resumes/knowledge/:id
DELETE /api/resumes/knowledge/:id
PUT  /api/resumes/knowledge/:id/review
POST /api/resumes/knowledge/:id/suggest
POST /api/resumes/knowledge/enrich
```

`POST /api/resumes/knowledge/filter-draft` 使用 `server/skills/knowledge-filter-assistant.md` 将自然语言映射为受限列表条件。只发送指令、不发送资料或简历；模型输出经服务端枚举白名单校验，客户端显示拟应用的条件和匹配条数，只有审核员点击应用才会更改当前视图。`POST /api/resumes/knowledge/enrich` 使用 `server/skills/knowledge-enrichment.md` 生成未持久化字段草案，可选 Tavily 搜索最多 5 条公开线索；建议中的官方 URL 必须与返回线索中的 URL 完全一致，且需明确属于资料主体的官网，否则清空。草案绑定请求时的表单内容；若名称、类别、字段或整理重点在等待期间发生变化，界面会阻止套用并要求重新生成。来源摘要与待核验项会一并展示。AI 不输出含金量评分或核验状态。新增和编辑写入接口会限制文本长度、列表数量和来源链接协议；证据来源最多保留 12 条，拒绝非 HTTP(S) 和重复链接。评分范围为 0 到 100。每次显式保存审核结果追加一条历史快照，最多保留最近 30 条，记录评分、理由、核验状态、时间、来源类型、引用的证据来源 ID 及完整来源快照。AI 生成阶段不写历史。来源状态是审核员维护的记录，不会因搜索结果被 AI 引用而自动设为已核对。

## 期刊会议图标与年度指标

`papers.md` 的 100 条期刊会议资料保留 `logo` 和 `impact_factor`，不改变稳定主键及原有人工评估历史。列表与详情页使用 `public/papers_logo/` 中经过解码、缩小和 PNG 转换的本地图标，`db/paper-logo-assets.json` 将原始资料路径映射到可显示资源。缺失、无法解码或浏览器加载失败时显示默认图标；详情可查看原来源及导入说明，官网 favicon 明确标注。

影响因子按原资料年份表格展示，保留数值、`null`、原资料状态、指标口径、来源说明与日期。会议显示“不适用”，国内期刊平台指标与 Clarivate JIF 不换算。`verified` 表示原资料整理者的标注，不是本次联网核验或人工复核。指标已随本地渠道背景传入 AI 分析，提示保留年份口径、不可外推个人成果质量；自建资料导出/导入同样保留这些嵌套字段并校验网址和图片相对路径。`annual_metrics/indexing=null` 仍指其它未整理字段，不否定独立的 `impact_factor`。

## 后续数据库升级建议

正式部署时可把本地 JSON 替换为 SQLite、PostgreSQL 或组织内部数据库，但应保留现有 API 契约和以下字段：`id`、`kind`、`title`、`aliases`、`field`、`organizer`、`region`、`summary`、`signals`、`officialUrl`、`significanceScore`、`scoreRationale`、`verificationStatus`、`updatedAt`。指标和认定信息建议额外建成带 `sourceUrl`、`sourceType`、`dataYear`、`checkedAt`、`evidenceNote` 的证据表，避免新的核验结果覆盖旧版本。

简历与资料的当前关联是“简历原文出现名称或别名”的确定性匹配。若后续需要人工确认、纠错或一对多关联，应增加关系表，至少包含 `candidateId`、`knowledgeId`、`evidence`、`reviewerConfirmed` 和 `createdAt`，不要把字符串命中直接当作事实。

拉丁字母缩写要求两侧不能紧贴其它拉丁字母或数字，但允许紧邻中文；候选资料超过六条时按实际命中词长度优先展示，避免宽泛短别名挤掉完整名称。该规则仍是文本线索，不等同于人工确认。

分析报告中的评分依据也支持回到 PDF 原文：点击评分历史中的证据句子后，阅读器会按页查找归一化后的精确文本并高亮命中的文字块。资料引用只扫描简历正文，不把姓名或岗位字段误当成奖项 / 论文 / 公司经历；资料详情列出具体命中的原文词，点击候选人会回到该 PDF 并尝试定位该词，示例简历则直接标色。找不到 PDF 精确文本时只提示未定位，不以近似命中冒充证据。两类交叉引用都应由审核员回看原文确认。
