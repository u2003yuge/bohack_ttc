# 成果资料库

`competitions.json` 保存从项目根目录 `competitions.md` 导入的 118 条赛事背景资料，包括全部 11 个业务字段、原始 ID、目录年份和备注。运行 `npm run import:competitions` 可校验并重新生成，重复运行不会追加重复条目。文件包含来源文件 SHA-256，随代码保存；资料库 API 和简历分析直接读取它，无需联网或重新运行模型。缺少的官网保持 `null`。

目录背景与下方按奖项、年份、赛道采集的核查报告用途不同。`report_year` 是目录年份，不是候选人获奖年份；已整理资料不自动变成当届核查报告，也不设置来源已核对状态。

`papers.json` 保存从项目根目录 `papers.md` 导入的 100 条期刊会议背景（55 个会议、45 本期刊）。运行 `npm run import:papers` 可校验并重新生成；重复运行结果一致，保留原始全部字段和源文件 SHA-256。资料包括名称及别名、类型、领域、出版或组织背景、官网、介绍、影响力、难度、分级及适用范围、来源读取方式、整理日期和注意事项。

`rankings` 的体系、版次、年份、等级、适用范围、来源、PDF 页码及核对说明分别保存；`sources` 保留 `access`，区分全文读取和检索缓存。`checked_on` 是整理者提供的日期，不是本次应用联网核验日期；导入不设置人工核验状态。`annual_metrics` 与 `indexing` 为 `null`，代表本批未核验。固定渠道背景不替代下方针对具体论文、版本与轨道的核查报告。

运行成果核查后，三类 skill 的 UTF-8 JSON 报告保存在本目录：

```text
db/<competition|paper|project>/<sha256>/
  report-<时间戳>-<随机 ID>.json
  latest.json
```

报告保留 skill 的六块结构，`latest.json` 单独记录可复用报告路径、采集时间和有效期。身份、年份或来源不足的报告仍保存，但不会更新缓存指针。默认有效期 30 天；过期后重新检索并新建报告，保留旧版本。读写失败会显示错误，不会静默覆盖损坏数据。

缓存键包含成果类型、skill 输入和原文明示的消歧信息。竞赛区分奖项、年份、组别、赛道、阶段和赛区；项目区分年份、机构和角色；论文区分标题、描述及已提供的作者、年份、DOI、arXiv、链接、轨道和版本。仅忽略大小写、首尾及重复空白和全半角差别，不自动合并简称或模糊近似名称。年龄不参与缓存键，不用于评价；命中后用当前简历输入重建报告的 input。

数据库保存固定赛事、期刊会议背景与成果研究报告，不保存整份 OCR 原文。简历证据片段随接口结果返回。动态核查报告被 Git 忽略，默认留在本机；固定目录随代码保存。

简历核查发现未知赛事或期刊会议时，标准化条目保存在 `db/library/custom-auto-<competition|journal>-<sha256>.json`。条目必须由实际读取的公开来源支持，保存主体名称、官网、介绍、影响力、难度、来源和整理时间；未确认主体、只有搜索摘要或缺少必需字段时只返回待补充，不创建文件。写入使用临时文件和目录锁，按类型与规范化名称去重。自动条目标记为待人工核验，不能证明个人获奖、论文发表或作者贡献；资料库页面下次加载或分析完成后会刷新显示。

来源只能来自本次检索工具实际返回的正文，搜索摘要不能作为已读取证据。公共资料不能证明简历持有人实际获奖、署名、参与或个人贡献。
