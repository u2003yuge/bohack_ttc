# 成果资料库

`competitions.json` 保存从项目根目录 `competitions.md` 导入的 118 条赛事背景资料，包括全部 11 个业务字段、原始 ID、目录年份和备注。运行 `npm run import:competitions` 可校验并重新生成，重复运行不会追加重复条目。文件包含来源文件 SHA-256，随代码保存；资料库 API 和简历分析直接读取它，无需联网或重新运行模型。缺少的官网保持 `null`。

目录背景与下方按奖项、年份、赛道采集的核查报告用途不同。`report_year` 是目录年份，不是候选人获奖年份；已整理资料不自动变成当届核查报告，也不设置来源已核对状态。

`competition-logo-assets.json` 保存 118 条目录赛事的图片对应结果；`competition-logo-review.json` 保存本地逐图检查决策、原清单字段和源文件 SHA-256。来源是 `competitions_logo/manifest.csv`，按原始 ID、完整赛事名及目录官网建立映射，不按数组顺序、模糊名称或合并后的资料库 ID 猜测。已有稳定 ID、评分、人工审核和原始赛事资料不变；新发现的赛事没有本地映射时继续显示默认图标。

本批 93 个源图片中，76 个可作为赛事标识或来源图标显示（75 张转换 PNG、1 张经过静态内容校验的 SVG）；17 个内容不匹配或非标识图片不发布，25 条目录赛事未提供图片。排除内容包括高校校徽、赞助商品牌、网页截图、照片、通用插画、通知封面和 Vite 默认图标。可用图又分为 37 个赛事标识、15 个相关机构标识、13 个服务平台图标和 11 个来源网站图标；机构及平台图标不作为赛事专属徽标。共享同一来源机构图片的赛事仍分别保留。

静态资源在 `public/competitions_logo/`，不依赖原桌面目录；缺图、排除图片或浏览器加载失败时显示默认奖杯。重新导入需要 Pillow：

```powershell
python scripts/import-competition-logos.py "C:\Users\20743\Desktop\competitions_logo"
```

导入器核对清单名称、ID、官网、原文件名及源文件哈希，内容或来源变化时要求更新本地图像检查记录，不会静默把旧决策应用到新图片。位图按实际格式解码、缩小到 256×256 内并统一 PNG；SVG 只允许无脚本、无外部资源的静态几何内容。该检查基于本地资料和图片可见内容，不代表本次联网核验，不改变竞赛人工核验和评分状态；原始 `competitions.md` / `competitions.json` 不被图标导入器改写。

`papers.json` 保存从项目根目录 `papers.md` 导入的 100 条期刊会议背景（55 个会议、45 本期刊）。运行 `npm run import:papers` 可校验并重新生成；重复运行结果一致，保留原始全部字段和源文件 SHA-256。资料包括名称及别名、类型、领域、出版或组织背景、官网、介绍、影响力、难度、分级及适用范围、来源读取方式、整理日期和注意事项。

`rankings` 的体系、版次、年份、等级、适用范围、来源、PDF 页码及核对说明分别保存；`sources` 保留 `access`，区分全文读取和检索缓存。`checked_on` 是整理者提供的日期，不是本次应用联网核验日期；导入不设置人工核验状态。`annual_metrics` 与 `indexing` 为 `null`，代表本批未核验。固定渠道背景不替代下方针对具体论文、版本与轨道的核查报告。

期刊会议还保留可选的 `impact_factor` 和 `logo`。前者按原始资料保存指标名称、2023–2025 年数值或 `null`、口径、状态、来源、日期和备注；`verified` 仅为原资料标注，不设置系统的人工核验状态。会议为 `not_applicable`，不将缺失指标填成 0，国内平台指标不与 Clarivate JIF 混用。旧版资料和自动入库条目可以没有这两个字段，备份导入会完整校验和保留它们。

`paper-logo-assets.json` 记录 100 个渠道的本地图标导入结果；`public/papers_logo/` 存放 55 个可显示 PNG，另有 10 个源文件无法解码、35 条原资料未提供图片，统一显示默认图标。原始 `logo.path/format/source_url/status/notes` 不被改写，清单单独保存源文件 SHA-256、实际格式、转换图片大小与哈希。所有图片在本地加载，不依赖用户桌面路径或远程热链。

需要重新导入本地图片时，先安装 Pillow（仅图片整理脚本需要，正常运行和构建不需要 Python），然后运行：

```powershell
python scripts/import-paper-logos.py "C:\Users\20743\Desktop\papers_logo"
npm run import:papers
```

图片导入按内容解码并限制尺寸至 256×256；网页、压缩的错误响应和不支持的内容不会直接放进静态目录。favicon 是官网/出版平台的标识线索，不保证是会议专属徽标；详情保留原始来源链接与处理说明。导入及转换均未重新联网确认图片身份或指标真实性。

运行成果核查后，三类 skill 的 UTF-8 JSON 报告保存在本目录：

```text
db/<competition|paper|project>/<sha256>/
  report-<时间戳>-<随机 ID>.json
  latest.json
```

报告保留 skill 的六块结构，`latest.json` 单独记录可复用报告路径、采集时间和有效期。身份、年份或来源不足的报告仍保存，但不会更新缓存指针。默认有效期 30 天；过期后重新检索并新建报告，保留此前版本。读写失败会显示错误，不会静默覆盖损坏数据。

缓存键包含成果类型、skill 输入和原文明示的消歧信息。竞赛区分奖项、年份、组别、赛道、阶段和赛区；项目区分年份、机构和角色；论文区分标题、描述及已提供的作者、年份、DOI、arXiv、链接、轨道和版本。仅忽略大小写、首尾及重复空白和全半角差别，不自动合并简称或模糊近似名称。年龄不参与缓存键，不用于评价；命中后用当前简历输入重建报告的 input。

数据库保存固定赛事、期刊会议背景与成果研究报告，不保存整份 OCR 原文。简历证据片段随接口结果返回。动态核查报告被 Git 忽略，默认留在本机；固定目录随代码保存。

简历核查发现未知赛事或期刊会议时，标准化条目保存在 `db/library/custom-auto-<competition|journal>-<sha256>.json`。条目必须由实际读取的公开来源支持，保存主体名称、官网、介绍、影响力、难度、来源和整理时间；未确认主体、只有搜索摘要或缺少必需字段时只返回待补充，不创建文件。写入使用临时文件和目录锁，按类型与规范化名称去重。自动条目标记为待人工核验，不能证明个人获奖、论文发表或作者贡献；资料库页面下次加载或分析完成后会刷新显示。

来源只能来自本次检索工具实际返回的正文，搜索摘要不能作为已读取证据。公共资料不能证明简历持有人实际获奖、署名、参与或个人贡献。
